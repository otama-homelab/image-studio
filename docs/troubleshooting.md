# トラブルシューティング

[ドキュメント一覧](../README.md#ドキュメント)

| 症状 | 確認と対処 |
|---|---|
| GHCRからpullできない | パッケージの公開範囲とpull権限を確認。非公開ならレジストリ認証を設定 |
| 起動時にモデル取得で止まる | ログと公式配布元への接続を確認。初回は取得に時間がかかる |
| `AMD ROCm GPU is required` | ホストのGPUドライバー、`/dev/kfd`・`/dev/dri`、renderグループ、GPU割り当てを確認 |
| `Permission denied` | UID/GID 1000が`/cache`と`/tmp`へ書き込めるか、GPUデバイスの権限を確認 |
| ホストでは起動したが画面に接続できない | ポート7860とバインド先を確認。Dockerの起動例はlocalhostのみ公開 |
| 初回の処理が遅い | モデル・GPUカーネルの初期化を待ち、2回目以降と比較 |
| 髪や肩の切り抜きが不自然 | 「髪・輪郭を精密に補正」をOFFにして比較。背景と被写体の色が近い写真などは誤差が出る |
| 顔が自動配置できない | 1人分の顔が明瞭な写真を使うか、画角・横位置・縦位置を手動調整 |
| 保存ボタンが消えた | 入力・設定の変更で古い出力を無効化する。処理または保存をもう一度実行 |
| ダウンロード先のファイルがない | 一時出力は期限切れやコンテナ交換で消える。再処理して手元へ保存 |
| 印刷写真の大きさが違う | 先にトリミングで寸法を決め、プリンターの100%／実際のサイズで印刷 |
| 300dpi以外というエラー | トリミングで300dpiのPNGに保存してから印刷へ渡す |
| 写真が用紙に収まらない | 写真の寸法を小さくするか、A4など大きい用紙を選ぶ |

## 起動を確認する

Dockerでは`docker logs image-studio`を確認します。モデル準備、AMD GPU名、`Running on local URL`の順に表示されます。GPUが使えないとアプリは起動しません。

KubernetesではPodの状態・events・ログを確認してください。ImagePullBackOff、ボリューム権限、GPU割り当て、アプリの起動失敗を分けて調べます。写真や認証値をログ・Issueへ貼らないでください。

## 問題を報告するとき

使っているバージョン、GPU/ROCm、問題が起きたタブ、設定、再現手順、値を伏せたエラーメッセージを添えてください。人物写真を公開Issueへアップロードせず、必要なら公開可能な再現用画像を使います。
